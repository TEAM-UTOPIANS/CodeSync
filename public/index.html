Everybody gets a cursor.
Not everybody gets a pen.

Shared editors usually hand the same pen to whoever shows up. CodeSync has three roles, and the room server checks each one. A viewer who edits the page in devtools still cannot change what anybody else sees.

Host

Runs the room

Whoever opens the room. They hold the keys and can hand them over.

  • Promotes and demotes anyone
  • Locks the room or sets a passcode
  • Removes people who should not be here
Editor

Writes the code

The default for a pairing session. Everything an editor types reaches the room.

  • Edits, renames and adds files
  • Runs the project for everyone
  • Saves checkpoints
Viewer

Watches along

Perfect for a class, a demo or an interview. They can still try things on their own copy.

  • Follows any cursor around the project
  • Runs the code privately
  • Can ask the host for a pen
The whole rulebook, in one table
Action Host Editor Viewer

The browser that opens a room keeps a secret host token and hands it over when it joins. The server only stores a hash of it, and the invite link never carries it, so passing the link around cannot pass the room around. Handing over the host role mints a fresh token for the new host.

Real projects, not one lonely file

Add files, rename them, throw them away. Everyone sees the same tabs the moment you do, and the whole set is handed to the compiler together, so your imports and includes behave.

Python finds its neighbours

Files sit next to each other in Pyodide's file system before every run, so import helper just works.

JavaScript can require them

The sandboxed worker resolves require("./util.js") against the other files in the room.

Web pages carry their own assets

An HTML file picks up the CSS and JavaScript it links to, and the preview refreshes while you type.

Headers and classes ride along

C, C++ and Java projects go up as a set, so your own headers and helper classes compile.

Checkpoints keep the whole thing

Name a version, then bring the entire project back for the room later. Not just the file you happened to be in.


          

        

      

    

  


  

    

      

        

          
33 languages, one tab

          
Python, JavaScript, MiniLang and web pages run right inside your browser and never leave it. The rest are built by public compiler services through a small serverless function, with a spare service standing by.

        

        

      

      

    

  


  

    

      
Three little pieces

      
Nothing here stores your code. A room lives in memory while people are in it, and every browser keeps its own copy.

      

        

          

            Your browser
            
The editor itself

            
Monaco, the editor from VS Code, on top of a conflict-free document. Two people can type in the same line and it still lands where you expect. Python and JavaScript execute here too, so most runs never touch a network.

          

          

            Room server
            
A small Socket.IO relay

            
It passes edits between everyone and owns the rules: roles, requests, the lock, the passcode, removals and checkpoints. It refuses a viewer's keystroke before it ever reaches the rest of the room, and forgets the room once the last person leaves.

          

          

            Compilers
            
Public build services

            
A serverless function checks and rate limits the request, then asks Compiler Explorer or Wandbox to build and run the project. No keys, no accounts, and a second service takes over when the first one is having a bad day.

Made by three people

      
CodeSync is an open source project by Team Utopians. The editor, the room server, the language layer and the little MiniLang interpreter all live in one repository.

      

      
Everything is on GitHub at TEAM-UTOPIANS/CodeSync. Issues and pull requests are welcome.
