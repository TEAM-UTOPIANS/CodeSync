Somebody
holds
the pen.

Most shared editors let everyone type at once and hope for the best. CodeSync has three roles, and the server is the one that enforces them. A viewer's keystrokes are refused on the wire, not hidden in the interface, so a locked file stays locked even if somebody opens the console.

What
happens
on the wire.

Four steps, and none of them involves a database. A room lives in memory while people are in it, and the code lives in every browser that has it open.

1

You open a room

The first browser to arrive presents a random token and becomes host. The server stores the hash of that token and nothing else.

2

Everyone edits one document

Every file is a Yjs text. Edits merge by themselves, in any order, so two people typing on the same line never destroy each other's work.

3

The server checks every write

An update from a viewer is dropped before it touches the document. Roles are a rule on the server, not a disabled button in the browser.

4

Run happens where it can

Python and JavaScript run in a worker on your own machine. The other languages go out to a public compiler service and come back with output, or with the line that broke.
